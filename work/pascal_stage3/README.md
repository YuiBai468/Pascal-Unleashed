# Pascal Unleashed · 共享尺度混合 INT8

目标采用全矩阵相对 Frobenius 误差 `<1%` 和 FP16 驻显存输入到 FP32 驻显存输出 `≥20 TFLOPS`。4096×4096×4096，单张 Tesla P40，驱动 582.78，cuBLAS 12.6.4。计时包含 GPU 统计、量化、打包、GEMM、FP32 重构与写回。开始计时时 A 和按转置布局存储的 B 已经在显存中。

| 配置 | 端到端等效 TFLOPS | 相对 Frobenius 误差 |
|---|---:|---:|
| 原三次 GEMM 混合，K 双路 1280，单次种子 | 20.18 | 0.993991% |
| 一次 GEMM，共享仿射尺度，K 双路 1344，最快扫描点 | 24.24 | 0.944341% |
| 一次 GEMM，共享仿射尺度，K 双路 1344，五种子复测 | 21.33–24.16 | 0.943118%–0.944341% |
| 一次 GEMM，共享仿射尺度，K 双路 1536，五种子复测 | 21.85–21.90 | 0.908555%–0.909820% |

精度参考为完整 FP64 GEMM，每次包含 16,777,216 个输出。五组复测每组计时九批，每批启动三次端到端流程，报告批次中位数。用相同的输入重复得到完全一致的全矩阵 FP32 输出。抽样另外核对了 INT32 点积与仿射行和，FP32 重构要求达到 1 ULP 内。早期复测日志中保留了一次抽样差异超出旧容差的记录，表格采用随后通过强化验证的复测。CUDA 测试还覆盖零行、常数行和非有限值标志。

同一快档在 4096 均匀随机输入上是 24.25T、0.458146%。极端值列输入是 24.22T、10.601725%，说明当前单个共享行尺度对跨分段异常值敏感。本轮没有把这种分布计入高斯验收，也没有验证真实 LLM 输入。

## 算法

高精度段的定点值写成 `q=5h+4g`，同时令 `r=-4h+5g`，所以 `qA*qB+rA*rB=41*(hA*hB+gA*gB)`。将高精度段的输入恢复单位定义为 `s/sqrt(41)`，两项整数点积都可以使用低精度段的结果尺度 `sA*sB`。每行的两个高精度坐标与低精度段的数据铺到同一个 INT8 输入里。高精度段一次近似保留两路并忽略 `rA*rB`。低精度段按 `x≈s*q+z` 仿射编码。零点交叉项来自行和和零点的乘积，加入同一个 FP32 输出 kernel。它们不需要单独的稀疏 gather 或 GEMM。

快档的 INT8 内维是 5440，即原始 4096 加 1344 个额外坐标。等效吞吐的分子仍按原始 `2MNK`。编解码全部在 P40 上执行。整数表示的 ±1035 全域及四百余万组标量乘积通过穷举校验。

## 复现

需要 Windows、NVIDIA 驱动、NumPy 和 CUDA 12 的 NVRTC/cuBLAS DLL。默认从 CUDA 版 PyTorch 的 `torch/lib` 获取，环境变量 `PASCAL_CUDA_DLLS` 可指定其它 DLL 目录。

```powershell
nvidia-smi -L
python frontier.py --gpu GPU-UUID --methods shared-affine --high-k 1344 1536 --seeds 2109 43 101 20261125 17 --samples 9 --output results/verify-local.json
```

`results/held-out-verified.json` 为完整复测原始数据。`frontier.json` 和 `affine-sweep.json` 记录同一高斯种子上的方案及算法号扫描。`low-error-sweep.json` 记录牺牲速度增加双路通道后的数据，`stress-*.json` 记录不同分布。
