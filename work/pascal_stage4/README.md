# Pascal Unleashed · P40 联合 INT8 编码

输入为两张驻留在 GPU 的 FP16 矩阵，计算 `A @ BT.T` 并写出 FP32。基准的 `M=N=K=4096`，主乘法使用一次 cuBLAS INT8 GEMM，按 INT32 累加。GPU 计时包含两边量化、INT8 布局转换、乘法和输出缩放。

## 实测

下表采用五组独立的标准正态 FP16 输入。吞吐量范围取每组 CUDA event 中位数的最小值和最大值。

| `1→2` 编码的位置数 | INT8 K | 等效吞吐量（T/s） | 全矩阵相对误差 |
| ---: | ---: | ---: | ---: |
| 0 | 6144 | 22.15–22.17 | 0.4637–0.4648% |
| 1024 | 6656 | 20.58–20.62 | 0.4172–0.4183% |
| 1280 | 6784 | 20.24–20.28 | 0.4047–0.4059% |
| 1408 | 6848 | 20.11–20.13 | 0.3986–0.3997% |

继续升到 1536 个位置时，种子 2109 的误差降到 0.3928%，多种输出布局下的吞吐量约为 19.93–19.94 T/s。

## 编码

将相邻两个 FP16 数视作二维向量 `x`。先用一对正交单位向量将 `x` 嵌入三维平面，再查表找到邻近的整数坐标 `q`。FP16 原值沿整数点的平面投影近似恢复。一次 INT8 点积得到两个投影的点积加上法向分量的乘积。

设 `P` 的两列是平面的正交单位向量，`n` 是对应的单位法向，`t = P @ x / s`。选点近似最小化 `||P.T @ (q - t)||² + λ (n.T @ q)²`。三维余数表只储存相对最近整数点的偏移。当前采用法向 `(3, 4, 5)`、`λ=0.002`、每个轴 16 个查表区间。每个输入行各有一个尺度 `s`，输出乘回相应的两个行尺度。

高精度配置把一部分 K 位置拆成标量，用二维空间中的直线进行 `1→2` 编码。其余位置继续用 `2→3` 编码。两种编码共享同一行尺度并拼到一次 INT8 GEMM 中。混合方案使用直线法向 `(3, 4)` 和 `λ=0.0001`。如果选出 `L` 个标量用 `1→2`，实际的 INT8 K 维为 `6144 + L/2`。

GPU 打包将投影值留在寄存器里，采用连续的字节写入。`--transpose-tile 64` 为右侧 INT8 数据启用 64×64 的字节转置。新路径要求 `K=4096`，64×64 转置要求右侧两维均为 64 的整数倍。

## 复跑

环境为 Windows 上的 Tesla P40（SM 6.1）、驱动 582.78、cuBLAS 12.6.4、Python 3.12 和 NumPy。`cuda.py` 默认从本机 PyTorch 安装目录读取 CUDA 12 DLL，也可用环境变量 `PASCAL_CUDA_DLLS` 指定 DLL 目录。先用 `nvidia-smi -L` 查 P40 的 UUID。

```powershell
python -u plane_gpu.py --gpu 'GPU-<P40的UUID>' --encoders plane_mixed_1408 plane_bytes_registers plane_mixed_1024 plane_mixed_1280 --transpose-tile 64 --seeds 2109 43 101 20261125 17 --samples 15 --output results/recheck.json
```

每组配置默认预热 60 次。每个种子记录 CUDA event 计时中位数，等效吞吐量按原始问题的 `2*M*N*K` 计算。每个输出矩阵与原始 FP16 输入的 FP64 参考结果比较，误差为 `||C-C_ref||F/||C_ref||F`。同时验证 32×32 的原始 INT32 点积和 FP32 写回，并检查重复执行的整张输出一致性。计时环节从数据驻留显存开始，排除了主机传输和首次编译。

上表的逐次计时和误差在 `results/plane-release.json`。`results/release-outliers.json` 使用沿 K 方向的少数 32 倍异常值进行压力测试。每行共用一个尺度使这些值扩大普通位置的量化步长，1408 位置配置的相对误差升至 13.73%。
