# Pascal Unleashed · 第二阶段 P40 实验

本阶段在单张 Tesla P40 上完成。基准和模型用例均使用 SM 6.1、Windows TCC、驱动 582.78、NVRTC 12.6 和 cuBLAS 12.6.4。主基准中利用率至少 50% 的 76 个采样点均为 1531 MHz，最高 29°C、237.44 W，降频原因字段为零。模型训练及 FP64 对照运行在 CPU。

## 验收结果

| 4096 独立高斯，种子 17 | GPU 驻留 FP16 至 FP32 | 全矩阵相对 Frobenius 误差 | 结论 |
|---|---:|---:|---|
| AR2，基数 16，融合输入行读取与打包 | 16.67 TFLOPS | 0.152610% | 本轮最快 |
| 双轮 AR2 + 二值 POPC 补偿，基数 18 | 12.94 TFLOPS | 0.120884% | 前沿中间点 |
| 三轮精确整数重构，基数 128 | 11.32 TFLOPS | 0.018817% | 精度达标选项中最快，且测试误差最低 |
| 三轮精确整数重构，基数 64 | 11.32 TFLOPS | 0.025166% | 精度达标 |
| 三轮精确整数重构，基数 32 | 11.31 TFLOPS | 0.043193% | 精度达标 |
| 全长组 16 级余数补偿，无裁剪 | 11.29 TFLOPS | 0.049242% | 精度达标 |
| 16 级余数补偿 + 双侧 FP32 稀疏修正 | 9.14 TFLOPS | 0.046045% | 精度达标 |

三轮基数 128 用种子 17、29、101 复测为 11.30–11.32 TFLOPS、0.018817%–0.018887%。主结果 12.144 ms，P95 12.184 ms。对应 FP16 位模式一致率为 59.79%，有限输出 ULP P50/P95/P99 为 0/4/18。精确整数重构是相对于已经量化的定点矩阵。联合目标 20 TFLOPS 与 0.05% 尚未同时出现。

主基准的 `A_main`、`B_prepacked`、`C_fp16`、`D_fixed_B`、`E_host_roundtrip` 按任务书定义记录。B 和 D 包含已准备好的稀疏索引及相应权重布局。E 包含同步上传 A/B 与下载结果，使用主机计时。A–D 用 CUDA Events，结果文件保留全部批次、P95、完整 FP64 参考的误差及非有限值计数。B 的输入按转置后的行连续布局提供。

## 硬件取舍

- 使用现有 SM 6.1 cuBLAS DP4A，两次主 GEMM 约 7.07 ms，折算 19.45 TFLOPS。SGEMM 同尺寸为 9.81 TFLOPS。自写融合通过重新分块与共享内存填充从同次 8.25 提到 9.64 TFLOPS，保留为实验路径。实际最快路径使用 cuBLAS。整数 `alpha=15` 和 `beta=15` 返回状态 7，整数 `alpha=beta=1` 已与 INT32 对照验证。
- 相同 K843 且含尾段的真实数据流中，双输出三值 DP4A 从 0.07095 ms 降至 0.05632 ms。三输出 DP2A 为 0.09757 ms，同工作量直接 DP4A 为 0.09435 ms。原型分别每 28 和 60 元素解包，跨段结果与 CPU 逐项一致。早期 `micro.json` 是段内操作数复用微基准。用于模式互比时优先读 `streamdot.json`。
- 4096 实矩阵三值掩码 POPC 核为 3.33 ms，二值为 1.62 ms。完整算法中已将两者用于低位补偿。三值配置的主要耗时仍来自稀疏 FP32 分支。低密度的 OP-16 虽然满足误差目标，端到端 9.14 TFLOPS，慢于三轮。对应稀疏核包含索引、输入 gather 与输出写回。
- 4096 一层整数 Strassen 使用保留头寸的编码，与同编码直接乘法的 FP32 输出逐元素一致。双轮路径直接计算 9.17 ms，Strassen 11.35 ms。三轮路径直接计算 12.14 ms，Strassen 16.76 ms。重组、暂存和 2048 子 GEMM 是成本来源。cuBLAS INT8 strided-batched 在这个测试上返回状态 7。头寸限制还降低了定点编码精度。
- SCC 验证覆盖共享进位区间穷举与一层 Strassen 上的 INT64 恒等式。对 2048 子块，单个稀疏三值×INT16 修正核在约 0.44% 和 3.03% 密度分别为 0.40 ms、2.12 ms。这已经吃掉该尺寸上极小的 Strassen 节省。基于该证据没有把 SCC 接到完整 GPU Strassen 路径，也没有给它填写端到端数据。

## 数据与边界

1024、2048、4096、`256×4096×2048`、`32×4096×4096` 共五种形状已测试。特殊分布包括均匀、FP16 有限范围、异常值、双侧冒尖、分块尺度跨度和重度抵消。极端分布下的相对误差需结合保存的绝对误差和参考范数解读。

模型验证使用 scikit-learn 的公开手写数字图像训练三层 MLP，留出集准确率 97.11%。用真实测试图像产生前向投影的激活和权重，并从训练样本的真实反向传播捕获权重梯度 GEMM。基数 128 路径前向和梯度全矩阵误差分别约 0.00368%、0.01688%。外部预训练大模型权重与 LLM 的实际激活或梯度未验证。

`proofs.py` 验证定点合法区间、INT32 原始点积与 INT64 重构上界，以及 SCC 共享进位。`test_stage2.py` 包含四个独立 CPU 单元测试。稀疏原型按行预留索引空间，当前用例需满足 `N` 和 `K` 是 4 的倍数、`K≤4096`。POPC 路径还需 `M=N` 和 `K` 被 32 整除。输入拒绝非有限值。

## 复现

需要 Windows、支持 SM 6.1 的 NVIDIA 驱动、Python、NumPy 与 CUDA 12 的 NVRTC/cuBLAS DLL。DLL 默认从 CUDA 版 PyTorch 的 `torch/lib` 定位，可用 `PASCAL_CUDA_DLLS` 覆盖。模型测试另外使用 PyTorch 与 scikit-learn。

```powershell
nvidia-smi -L
.\Run-Stage2.ps1 -Gpu GPU-UUID -Mode Quick
.\Run-Stage2.ps1 -Gpu GPU-UUID -Mode Full
```

`results/pareto.csv` 针对种子 17 的全矩阵 FP16 端到端结果标记非支配项，其他种子的结果单列。`results/*.json` 含原始批次及指标，`*.telemetry.csv` 含时钟和温度，根目录 `*.log` 为运行日志。CUDA 源可由 Python 直接用 NVRTC 编译，附有 PTX/cubin。早期可运行版本留在原工程。

## 给数学组的问题

20T 对应 6.872 ms。两轮 cuBLAS INT8 本身已用 7.07 ms，添加额外的密集修正没有预算。若保留一轮实测约 3.53 ms 的 INT8 主算，剩余约 3.34 ms 需同时覆盖编码、修正、重构。

请给出一个在**独立高斯 FP16**上可检验的补偿分解，让一次密集 INT8 主算配合足够小的低位工作把全矩阵误差压到 0.05% 内。实测 4096 二值 POPC 为 1.62 ms，三值为 3.33 ms。请明确需要多少个 bitplane，以及哪些能共享掩码、输入读取和输出累加。若使用稀疏补偿，请估算实际索引访存与输出更新次数，并说明能否把稀疏分量约束成连续列或块。
